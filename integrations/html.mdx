If you already have a page to put the documentation in, you can load the Bruno docs renderer directly with a script tag. No server package is involved: the browser fetches the collection and renders it.

This is the right choice when you are serving a static site, embedding docs in an existing developer portal, or using a framework that does not have a package yet.

## Add the renderer to a page

```html
<head>
  <link rel="stylesheet" href="https://cdn.usebruno.com/api-docs/api-docs.css">
  <script src="https://cdn.usebruno.com/api-docs/api-docs.js"></script>
</head>
<body>
  <div id="bruno-api-docs"></div>
  <script>
    new Bruno.apiDocs('#bruno-api-docs', {
      url: 'https://cdn.example.com/docs/opencollection.yml',
      theme: 'dark'
    })
  </script>
</body>
```

Three things are happening:

1. An empty container marks where the docs are drawn.
2. The renderer bundle is loaded from Bruno's CDN.
3. `Bruno.apiDocs` mounts the docs into the container and fetches the collection from `url`.

## Pointing at your collection

The renderer needs the collection document, either fetched from a URL or handed over directly. Collection folders (`collectionPath`) are not supported in the browser; use a bundled `opencollection.yml` URL or inline `content`.

Source precedence when more than one is set: `content` > `collectionPath` > `url`.

<CodeGroup>

```js Hosted YAML over HTTPS
new Bruno.apiDocs('#bruno-api-docs', {
  url: 'https://cdn.example.com/docs/opencollection.yml'
})
```

```js Pass the document inline
new Bruno.apiDocs('#bruno-api-docs', {
  content: collectionObject
})
```

</CodeGroup>

Use `url` with a full `https://` link to a hosted, bundled YAML file. Use `content` when your page already has the document, for example from a build step that inlined it. See [Configuration](/integrations/configuration) for every option.

<Warning>
  With this approach the whole document reaches the browser. Filtering out environments and requests happens on the server, so publish a document that is already safe to hand over. The [framework packages](/integrations/overview#filtering-is-deletion-not-hiding) do that filtering for you.
</Warning>

## Options

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `url` | `string` | one source required | Absolute `https://` URL of a hosted, bundled `opencollection.yml` |
| `content` | `object` or `string` | one source required | The document itself, as an object or YAML/JSON text |
| `environments` | `{ include?: string[], exclude?: string[] }` or `'*'` | none | Filter environments by name, or `'*'` for all (hiding in the client) |
| `tags` | `{ include?: string[], exclude?: string[] }` or `'*'` | `'*'` | Filter requests by tags, or `'*'` for all (hiding in the client) |
| `theme` | `string` | `light` | Default theme |
| `pageTitle` | `string` | `API Documentation` | Browser tab title |
| `logo` | `string` | none | Logo in the docs header, as a URL or data URI |
| `repositoryUrl` | `string` | none | Git URL behind the **Open in Bruno** button |

Tell Bruno where the collection comes from with either `url` (a public `https://` YAML file) or `content` (the document already in the page). Use one of them, not both.

## Full example

```html
<!doctype html>
<html>
  <head>
    <meta charset="utf-8" />
    <title>Payments API</title>
    <link rel="stylesheet" href="https://cdn.usebruno.com/api-docs/api-docs.css">
  </head>
  <body>
    <div id="bruno-api-docs"></div>

    <script src="https://cdn.usebruno.com/api-docs/api-docs.js"></script>
    <script>
      new Bruno.apiDocs('#bruno-api-docs', {
        url: 'https://cdn.example.com/docs/opencollection.yml',
        pageTitle: 'Payments API',
        logo: '/logo.svg',
        repositoryUrl: 'https://github.com/acme/payments-collection'
      })
    </script>
  </body>
</html>
```

## Linking to a request

The renderer routes with the URL hash, so any page inside the docs can be linked to directly:

```text
/docs/#/catalog/list-products
```
