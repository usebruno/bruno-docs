This guide walks through installing the Bruno Backstage plugin so collections appear as `kind: Bruno` entities in your catalog.

## How it works

<Steps>
  <Step title="Register a collection">
    Add a `kind: Bruno` descriptor with a `catalog-info.yaml`, an entry in `app-config.yaml`, or the **Add Bruno Collection** wizard. Point `spec.url` at the folder that holds `bruno.json` or `opencollection.yml`, and optionally link APIs with `spec.partOf`.
  </Step>
  <Step title="Backstage reads from Git">
    The plugin backend uses your existing `integrations.*` credentials to read the collection. It builds an OpenCollection document into `spec.definition` and keeps metadata such as request count in sync on the catalog processing loop.
  </Step>
  <Step title="Collections appear in the portal">
    The Bruno dashboard lists every `kind: Bruno` entity. Linked APIs show a **Bruno Collections** card, and each collection page shows ownership, related APIs, and an **API Docs** tab.
  </Step>
  <Step title="Open docs or Bruno">
    Developers read Bruno docs inside Backstage, or use **Open Collection** to hand the repository off to the Bruno desktop app when they need to send or edit requests.
  </Step>
</Steps>

## Prerequisites

- A Backstage app on the **new backend system**
- Frontend: **new frontend system**, or **legacy frontend** (legacy wiring is in progress for Beta)
- SCM access configured under `integrations.*` for the hosts that hold your collections
- Built and tested on **Backstage 1.54** (see the compatibility table published with the Beta release)

## Packages

| Package | Installed in | Role |
|---|---|---|
| `@usebruno/backstage-plugin-bruno` | `packages/app` | Dashboard, wizard, entity cards, API Docs tab |
| `@usebruno/backstage-plugin-bruno-backend` | `packages/backend` | Catalog module + `/api/bruno` routes |
| `@usebruno/backstage-plugin-bruno-common` | (dependency) | Shared types, permissions, descriptor builder |

Translations: `import { brunoTranslationRef } from '@usebruno/backstage-plugin-bruno/alpha'`

## 1. Install the backend

```bash
yarn --cwd packages/backend add @usebruno/backstage-plugin-bruno-backend
```

```ts
// packages/backend/src/index.ts
import { catalogModuleBruno } from '@usebruno/backstage-plugin-bruno-backend';

backend.add(import('@usebruno/backstage-plugin-bruno-backend')); // /api/bruno routes
backend.add(catalogModuleBruno); // kind: Bruno in the catalog
```

Both lines are required. Without the catalog module, `kind: Bruno` entities are rejected.

## 2. Install the frontend

### New frontend system

```bash
yarn --cwd packages/app add @usebruno/backstage-plugin-bruno
```

```tsx
// packages/app/src/App.tsx
import brunoPlugin, {
  brunoAppModule,
  brunoCatalogModule,
} from '@usebruno/backstage-plugin-bruno';

export default createApp({
  features: [
    brunoPlugin, // omit if app.packages feature discovery is on
    brunoAppModule, // kind:bruno icon
    brunoCatalogModule, // Bruno icon in catalog lists and links
  ],
});
```

The pull-request flow opens the PR as the signed-in user through a GitHub authorization popup. Configure a GitHub OAuth app under `auth.providers.github` and add `@backstage/plugin-auth-backend-module-github-provider` to the backend. Users can sign in with any provider; they only authorize GitHub when they submit a pull request. Without it, PR creation fails and only **Download** works.

### Legacy frontend system

Legacy export names are finalized during Beta. Wire routes and entity page slots roughly as follows:

```tsx
// packages/app/src/App.tsx
<Route path="/bruno" element={<BrunoDashboardPage />} />
<Route path="/bruno/add" element={<AddBrunoCollectionPage />} />
```

```tsx
// packages/app/src/components/catalog/EntityPage.tsx
// On API entity Overview:
<EntityBrunoCollectionsCard />

// On kind: Bruno entity:
<EntityLayout.Route path="/" title="Overview">
  <EntityAboutCard />
  <EntityBrunoRelatedApisCard />
</EntityLayout.Route>
<EntityLayout.Route path="/collection-docs" title="API Docs">
  <EntityBrunoApiDocsContent />
</EntityLayout.Route>
```

## 3. Allow Bruno in the catalog and configure Git

```yaml
# app-config.yaml
catalog:
  rules:
    - allow: [Component, System, API, Resource, Location, Bruno] # required

integrations:
  github:
    - host: github.com
      token: ${GITHUB_TOKEN}
```

Public GitHub repos work without a token, but are rate limited to 60 requests per hour. Private repos, GitLab, and Bitbucket Cloud always need an `integrations` entry.

A GitHub fine-grained token needs read access to **Contents**, **Metadata**, and **Commit statuses**.

## What you get after install

| Surface | Where | Purpose |
|---|---|---|
| **Bruno dashboard** | Sidebar → Bruno (`/bruno`) | Catalog table of `kind: Bruno` with filters and **Add Bruno Collection** |
| **Bruno Collections card** | API entity Overview | Collections that are `partOf` this API |
| **Associated APIs card** | Bruno entity Overview | APIs this collection covers |
| **API Docs tab** | Bruno entity (`/collection-docs`) | Bruno docs renderer (read-only in Beta) |
| **Open Collection** | Bruno entity About card | Opens Bruno via `https://fetch.usebruno.com/?url=...` |

Collections refresh on the catalog processing loop using conditional requests (ETag / latest-commit). There is no separate Sync button; use the catalog's native refresh to force an update.
