[Backstage](https://backstage.io/) is an open-source developer portal that helps engineering teams discover, manage, and understand their software in one place.

## What is Backstage?

Originally developed by Spotify, Backstage is an open-source framework for building internal developer portals. It helps companies organize their services, APIs, documentation, infrastructure, and developer tools in a single catalog.


**Example:** Imagine a company with 50 microservices, maintained by different engineering teams.

A new developer joins and wants to know:

- Where is the authentication API?
- Which team owns it?
- Where can I find its documentation?
- How can I test its endpoints?

Without a central portal, they might need to search GitHub repositories, ask teammates, find Swagger documentation, and import API collections manually. With Backstage, the company can bring this information together in one place.



## What problem does Bruno solve?

At organizations that already use Bruno and Backstage, collections often live in folders across many repos. They sit outside the API catalog the company maintains in Backstage.

That leaves gaps like:

- Which Bruno collections exist for this API?
- Who owns them?
- Where do I open them to send requests or read Bruno docs?

A developer can find the OpenAPI definition on an API page, but still has to hunt for the matching Bruno collection elsewhere.

## How Bruno fits in

- Bruno registers each collection as a `kind: Bruno` catalog entity, linked to the APIs it covers
- From Backstage you can find the collection, read its API docs in the portal, and open it in Bruno when you need to send requests
- Git stays the source of truth. Backstage reads collections with your existing SCM credentials. No Bruno cloud, no new API key

## Example: a new developer joining a team

Suppose a developer joins a company and needs to integrate its payment API.

<Steps>
  <Step title="Discover the API">
    They open Backstage and search for the Payment Service. They can see which team owns it and which APIs it provides.
  </Step>
  <Step title="Explore Bruno API Docs">
    They open the Bruno documentation tab and find endpoints such as `POST /payments`, request examples, and test information.
  </Step>
  <Step title="Try an API request">
    With a properly configured playground, they can select a permitted environment, provide authentication, and test the API directly.

    <Note>
      In Beta the API Docs tab is read-only. In-portal playground execution is planned for GA. Until then, use **Open in Bruno** to send requests from the desktop app.
    </Note>
  </Step>
  <Step title="Collaborate">
    If they find an outdated example, they can follow a link to the collection repository and propose an improvement through a GitHub pull request.
  </Step>
</Steps>
