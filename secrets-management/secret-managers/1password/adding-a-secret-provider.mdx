Bruno integrates with 1Password using a **Service Account token**. Configure the provider once in **Preferences**, then attach it to any collection environment. <PremiumBadge noLink />

## Prerequisites

1. Create a [1Password Service Account](https://developer.1password.com/docs/service-accounts/) with access to the vaults you need.
2. Copy the Service Account token (it starts with `ops_`).

## Configuration Steps

1. Go to **Preferences** and open the **Secrets Manager** section.
2. Click **+ Add Secret Manager**.
3. Select **1Password** (described as 1Password secrets with service account token auth).
4. Enter:
   - **Name** - a label for this account in Bruno (for example `Production Secrets` or `1pass`)
   - **Service Account Token** - your `ops_...` token
5. Click **Test Connection** to verify Bruno can reach 1Password with that token.
6. Click **Add** to save the account.

Once saved, the account appears in the **Secrets Manager** list and is available when you configure **External Secrets** on an environment.

Calls to 1Password use the same **proxy** settings as the rest of the Bruno app.

## Exporting as a .env file

Once a provider is saved, you can export its configuration as a `.env` file from **Preferences** > **Secrets Manager**. That is useful for the Bruno CLI or CI without typing the token by hand.

1. In the **Secrets Manager** list, hover over the 1Password account.
2. Click the **Export as .env** icon.
3. Bruno writes the credentials to a `.env` file on your machine.

<Warning>
  The exported `.env` file contains your Service Account token in plain text. Add it to `.gitignore` immediately and never commit it to version control.
</Warning>

Pass the exported file to the CLI:

```bash
bru run collection/ --env local --secrets-env-file ./secrets.env
```

The token is supplied as `BRUNO_ONE_PASSWORD_SERVICE_ACCOUNT_TOKEN` in that file. See [Using secrets](./using-secrets#using-secrets-with-bruno-cli).
